# 스택 성장

프로젝트 2에서는 스택이 `USER_STACK`에서 시작하는 단일 페이지였고, 프로그램의 실행은 이 크기로 제한되었습니다. 이제 스택이 현재 크기를 초과하면 필요한 만큼 추가 페이지를 할당합니다。

추가 페이지는 그 접근이 "스택 접근"으로 보일 때에만 할당해야 합니다。 스택 접근과 다른 접근을 구분하기 위한 휴리스틱을 고안하세요。

사용자 프로그램이 스택 포인터 아래 영역에 쓰기를 수행하는 것은 버그입니다。 실제 운영체제는 언제든 프로세스에 "시그널"을 전달하기 위해 인터럽트를 발생시킬 수 있고, 이는 스택의 데이터를 변경할 수 있기 때문입니다。 그러나 x86-64의 `PUSH` 명령은 스택 포인터를 조정하기 전에 접근 권한을 검사하므로 스택 포인터보다 8바이트 아래에서 페이지 폴트가 발생할 수 있습니다。

현재 사용자 프로그램의 스택 포인터 값을 얻을 수 있어야 합니다。 시스템 호출이나 사용자 프로그램에 의해 발생한 페이지 폴트 상황에서는 각각 `syscall_handler()` 또는 `page_fault()`에 전달되는 `struct intr_frame`의 `rsp` 멤버에서 이를 가져올 수 있습니다。 페이지 폴트를 이용해 잘못된 메모리 접근을 감지하려면 커널에서 페이지 폴트가 발생하는 경우도 처리해야 합니다。 프로세서가 예외로 인해 사용자 모드에서 커널 모드로 전환할 때만 스택 포인터를 저장하기 때문에, `page_fault()`에 전달되는 `struct intr_frame`에서 `rsp`를 읽으면 사용자 스택 포인터가 아닌 정의되지 않은 값이 나올 수 있습니다。 초기 사용자→커널 전환 시 `rsp`를 `struct thread`에 저장하는 것과 같은 다른 방식을 마련해야 합니다。

스택 성장 기능을 구현하세요。 이를 위해 먼저 `vm/vm.c`의 `vm_try_handle_fault`를 수정하여 스택 성장을 식별하도록 하고, 스택 성장이 확인되면 `vm_stack_growth`를 호출하세요。 `vm_stack_growth`를 구현합니다。

```c
bool vm_try_handle_fault (struct intr_frame *f, void *addr,
	bool user, bool write, bool not_present);
```

이 함수는 `userprog/exception.c`의 `page_fault`에서 페이지 폴트 예외를 처리하는 동안 호출됩니다。 이 함수에서는 페이지 폴트가 스택 성장으로 처리 가능한 유효한 경우인지 검사해야 합니다。 스택 성장으로 처리할 수 있다고 확인되면、 폴트 주소로 `vm_stack_growth`를 호출하세요。

```c
void vm_stack_growth (void *addr);
```

이 함수는 익명 페이지를 하나 이상 할당하여 `addr`이 더 이상 페이지 폴트를 발생시키지 않도록 스택 크기를 늘립니다。 할당을 처리할 때 `addr`을 `PGSIZE` 단위로 내림(round down)하는 것을 잊지 마세요。

대부분의 운영체제는 스택 크기에 절대적인 제한을 둡니다。 일부 운영체제는 `ulimit`과 같이 사용자가 조정할 수 있게 합니다。 많은 GNU/Linux 시스템에서 기본 제한은 8MB입니다。 이 과제에서는 스택 크기를 최대 1MB로 제한하세요。

이제 스택 성장 관련 테스트들이 통과해야 합니다。

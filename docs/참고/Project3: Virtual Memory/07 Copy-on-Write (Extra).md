# Copy-on-Write (Extra)

Pintos에서의 Copy-on-Write(COW) 메커니즘을 구현합니다.

Copy-on-Write는 동일한 물리 페이지 인스턴스를 여러 프로세스가 공유하도록 하여 복사 비용을 늦추고 성능을 높이는 자원 관리 기법입니다. 어떤 자원이 여러 프로세스에 의해 사용될 때 보통은 충돌을 방지하기 위해 각 프로세스가 자원의 복사본을 가져야 합니다. 그러나 자원이 수정되지 않고 읽기 전용으로만 사용되는 경우에는 물리 메모리에 복사본을 여러 개 둘 필요가 없습니다.

예를 들어 `fork`로 새로운 프로세스를 만들 때 자식은 부모의 자원을 자신의 가상 주소 공간으로 상속받아야 합니다. 일반적으로 가상 메모리에 내용을 추가하려면 물리 페이지를 할당하고 데이터를 프레임에 쓰고 페이지 테이블에 가상->물리 매핑을 추가하는 작업이 필요하며, 이는 비용이 많이 듭니다.

하지만 COW를 사용하면 새 복사본을 위해 즉시 새로운 물리 페이지를 할당하지 않습니다. 기술적으로 데이터는 이미 물리 메모리에 존재하므로, 자식 프로세스의 페이지 테이블에 부모가 참조하던 동일한 물리 프레임으로의 가상->물리 매핑만 추가하면 됩니다. 이때 부모와 자식은 동일한 물리 페이지의 동일한 데이터를 읽게 되며, 가상 주소 공간은 분리되어 있으므로 서로 격리됩니다. 운영체제만이 이들이 동일한 프레임을 참조하고 있음을 알고 있습니다. 만약 어느 한 프로세스가 공유된 자원을 수정하려 하면, 그때 해당 프로세스만을 위해 새로운 물리 페이지를 할당하고 내용을 복사하여 별도의 복사본을 만듭니다. 즉, 실제 복사 작업은 최초의 쓰기 시점까지 지연됩니다.

이를 위해 운영체제는 COW 페이지에 대한 쓰기 시도를 감지할 수 있어야 합니다. 이를 달성하기 위해 운영체제는 "쓰기 보호(write-protect)" 메커니즘을 사용합니다. 아이디어는 간단합니다: 쓰기 접근에서 페이지 폴트를 발생시키도록 해당 페이지를 쓰기 불가능으로 표시합니다. 메모리 관리 시스템의 지원으로, 쓰기 보호된 페이지는 단순히 PTE를 수정하여 쓰기 비트를 끄면 됩니다. 쓰기 시도 시 페이지 폴트 핸들러는 해당 폴트가 COW로 인한 것인지 판단하고, 맞다면 새로운 프레임을 할당하여 내용을 복사한 뒤 해당 프로세스에만 쓰기 가능한 매핑을 설정해 줍니다.

이 과제에서는 `fork`에 대해서만 COW를 구현하면 됩니다. 자식 프로세스가 부모로부터 자원을 상속할 때, 해당 자원은 자식이 수정할 때까지 동일한 물리 데이터를 참조할 수 있습니다. 또한 모든 쓰기 보호된 페이지는 추방(eviction)의 후보가 됩니다.

기본 테스트 케이스만 제공되므로, 가능한 경우들을 모두 고려해야 합니다. 작은 힌트: 파일 기반 페이지도 공유할 수 있도록 구현해야 합니다. 이 확장 과제의 채점은 숨겨진 테스트도 포함됩니다.

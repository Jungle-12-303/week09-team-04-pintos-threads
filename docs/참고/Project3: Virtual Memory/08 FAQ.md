# FAQ

Q: Project 3을 구현하려면 Project 2가 제대로 동작해야 하나요?
A: 예.

Q: 페이지 폴트를 처리한 뒤 프로세스는 어떻게 재개되나요?
A: `page_fault()`에서 반환하면 현재 사용자 프로세스가 재개됩니다. 그 후 CPU는 명령 포인터가 가리키는 명령을 다시 시도합니다.

Q: 왜 사용자 프로세스가 때때로 스택 포인터보다 위의 주소에서 폴트하나요?
A: 스택 성장 테스트에서, 사용자 프로그램이 현재 스택 포인터보다 위의 주소에서 폴트하는 것을 관찰할 수 있습니다. 이는 스택 연산과 예외 처리 시점 차이로 인해 발생할 수 있습니다(예: 일부 명령은 스택 포인터를 조정하기 전/후에 메모리에 접근합니다).

Q: 가상 메모리 시스템이 데이터 세그먼트 확장을 지원해야 하나요?
A: 아니요. 데이터 세그먼트의 크기는 링커가 결정합니다. 현재 Pintos에는 동적 메모리 할당(커널 내 malloc 등)이 없으므로, 데이터 세그먼트 확장은 반드시 필요하지 않습니다(사용자 수준에서 메모리 매핑 파일로 흉내낼 수는 있습니다). 잘 설계된 시스템이라면 데이터 세그먼트 확장을 추가해도 큰 복잡도 증가는 없습니다.

Q: 페이지 프레임을 할당할 때 왜 `PAL_USER`를 사용해야 하나요?
A: `palloc_get_page(PAL_USER)`에 `PAL_USER`를 전달하면 메모리를 커널의 주 풀 대신 사용자 풀에서 할당합니다. 사용자 풀에서 페이지가 부족하면 사용자 프로그램만 페이징되지만, 커널 풀에서 페이지가 부족하면 많은 커널 함수들이 메모리를 얻지 못해 광범위한 실패가 발생할 수 있습니다. 다른 상위 수준의 할당자를 `palloc_get_page()` 위에 덧댈 수는 있지만, 근본적인 할당 메커니즘으로 `palloc_get_page(PAL_USER)`를 사용하는 것이 바람직합니다. 또한 `-ul` 커널 명령줄 옵션으로 사용자 풀 크기를 제한하면 다양한 사용자 메모리 크기로 VM을 테스트하기 쉬워집니다。

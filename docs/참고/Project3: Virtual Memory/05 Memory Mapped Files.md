# 메모리 매핑 파일

이 절에서는 메모리-매핑 페이지(memory-mapped pages)를 구현합니다。 익명 페이지와 달리 메모리-매핑 페이지는 파일 기반 매핑(file-backed mapping)입니다。 페이지의 내용은 기존 파일의 데이터와 일치합니다。 페이지 폴트가 발생하면 즉시 물리 프레임을 할당하고 파일에서 데이터를 복사해 메모리에 채웁니다。 메모리-매핑 페이지가 언맵(unmap)되거나 스왑아웃될 때, 내용의 변경이 파일에 반영되어야 합니다。

## `mmap` 와 `munmap` 시스템 콜
메모리 매핑 파일을 위한 두 시스템 콜 `mmap`과 `munmap`을 구현하세요。 VM 시스템은 매핑 영역에 대해 페이지를 지연 할당(lazy)해야 하며, 매핑의 백업 저장소로 매핑된 파일 자체를 사용해야 합니다。 이 두 시스템 콜은 `vm/file.c`에 정의된 `do_mmap`과 `do_munmap`을 사용해 구현하면 됩니다。

```c
void *mmap (void *addr, size_t length, int writable, int fd, off_t offset);
```

파일 디스크립터 `fd`로 열린 파일의 `offset` 바이트부터 시작하는 `length` 바이트를 프로세스의 가상 주소 공간 `addr`에서 매핑합니다。 파일 전체는 `addr`에서 연속적인 가상 페이지들로 매핑됩니다。 파일 길이가 `PGSIZE`의 배수가 아니라면、 마지막 매핑 페이지의 일부 바이트들은 파일 끝을 넘어 "튀어나온" 상태가 됩니다。 이러한 바이트들은 페이지가 폴트되어 로드될 때 0으로 설정하고, 페이지를 디스크에 다시 쓸 때는 버려야 합니다。 성공하면 매핑된 가상 주소를 반환하고, 실패하면 NULL을 반환합니다(NULL은 유효한 매핑 주소가 아닙니다)。

`mmap`은 다음과 같은 경우 실패해야 합니다：
- `fd`로 열린 파일의 길이가 0인 경우
- `addr`가 페이지 정렬(page-aligned)되어 있지 않은 경우
- 매핑하려는 페이지 범위가 스택 또는 실행 시 로드된 페이지를 포함하여 기존 매핑과 겹치는 경우

Linux에서는 `addr`가 NULL이면 커널이 적절한 주소를 찾아 매핑합니다。 단순화를 위해 이 과제에서는 주어진 `addr`에서만 매핑을 시도하면 됩니다。 따라서 `addr`가 0이면 실패해야 합니다(일부 Pintos 코드가 가상 페이지 0이 매핑되지 않았다고 가정하기 때문입니다)。 또한 `length`가 0이면 실패해야 합니다。 콘솔 입력/출력을 나타내는 파일 디스크립터들은 매핑할 수 없습니다。

메모리-매핑 페이지는 익명 페이지와 마찬가지로 지연 방식으로 할당되어야 합니다。 `vm_alloc_page_with_initializer` 또는 `vm_alloc_page`를 사용하여 페이지 객체를 생성할 수 있습니다。

```c
void munmap (void *addr);
```

`addr`로 지정된 주소 범위에 대한 매핑을 언맵합니다。 `addr`는 동일 프로세스에서 이전에 `mmap`이 성공적으로 반환한 가상 주소여야 하며, 아직 언맵되지 않은 매핑이어야 합니다。

모든 매핑은 프로세스가 종료될 때(명시적 `exit` 포함) 암묵적으로 언맵됩니다。 매핑이 언맵될 때(명시적이든 암묵적이든), 프로세스가 그 페이지들에 대해 쓴 모든 변경 내용은 파일에 기록되어야 하며, 쓰지 않은 페이지는 기록해서는 안 됩니다。 그런 다음 페이지들은 프로세스의 가상 페이지 목록에서 제거됩니다。

파일을 닫거나 제거해도 그 파일의 매핑은 언맵되지 않습니다。 한 번 생성된 매핑은 `munmap`이 호출되거나 프로세스가 종료될 때까지 유효합니다(Unix 관습)。 매핑마다 독립적인 파일 참조를 얻기 위해 `file_reopen` 함수를 사용하세요。

두 개 이상의 프로세스가 동일한 파일을 매핑한 경우, 이들이 일관된 데이터를 보아야 한다는 요구사항은 없습니다。 Unix는 두 매핑이 같은 물리 페이지를 공유하도록 처리하며、 `mmap` 시스템 콜은 매핑이 공유(shared)인지 개인(private, 즉 COW)인지 지정할 수 있는 인자를 제공합니다。

필요시 `vm/vm.c`의 `vm_file_init`과 `vm_file_initializer`를 수정할 수 있습니다。

```c
void vm_file_init (void);
```

파일 기반 페이지 서브시스템을 초기화합니다。 이 함수에서 파일 기반 페이지와 관련된 설정을 수행하세요。

```c
bool file_backed_initializer (struct page *page, enum vm_type type, void *kva);
```

파일 기반 페이지를 초기화합니다。 이 함수는 먼저 `page->operations`에 파일-기반 페이지용 핸들러를 설정합니다。 페이지 구조체에 백업 파일과 같은 정보를 업데이트해야 할 수 있습니다。

```c
static void file_backed_destroy (struct page *page);
```

연결된 파일을 닫음으로써 파일 기반 페이지를 파괴합니다。 내용이 더러워져(dirty) 있다면 변경 내용을 파일로 다시 써야 합니다。 이 함수에서는 페이지 구조체 자체를 해제할 필요는 없습니다。 `file_backed_destroy`를 호출한 쪽에서 페이지 구조체의 해제를 처리합니다。
